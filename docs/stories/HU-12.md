## Objetivo
Agregar campo de país al perfil del usuario y priorizar resultados de búsqueda según el país, empezando por Colombia.

- **D5:** CO primero, luego LAC (MX, AR, PE, CL, VE, EC)

## Modelo de datos

### Migración Prisma (`prisma/schema.prisma`)

```prisma
model User {
  // ... campos existentes ...
  countryCode  String?  // ISO 3166-1 alpha-2: "CO", "MX", "AR", etc.
}

model Food {
  // ... campos existentes ...
  regionCode   String?  // null = global, "CO" = colombiano, "LAC" = latinoamericano genérico
  @@index([regionCode])
}
```

### Migración Turso producción
```sql
ALTER TABLE User ADD COLUMN countryCode TEXT;
ALTER TABLE Food ADD COLUMN regionCode TEXT;
CREATE INDEX Food_regionCode_idx ON Food(regionCode);
```

## Endpoints nuevos

### `GET /api/foods/regional?country=CO&limit=20`
**Request:** query params `country` (ISO 3166-1 alpha-2) y `limit` (1-50)
**Response:**
```json
{
  "foods": [
    { "id": 1, "nombre": "Arepa", "cal": 220, "p": 5, "c": 45, "f": 2, "regionCode": "CO", "source": "user" }
  ]
}
```

### `GET /api/foods?q=...` (modificado)
Ahora aplica prioridad regional:
```ts
// Pseudocódigo del order by
const userCountry = session.user.countryCode ?? null;
orderBy: [
  { regionCode: userCountry ? { equals: userCountry } : "asc" },
  { source: "asc" },
  { usageCount: "desc" },
]
```

### API (Vitest + test DB)

**`__tests__/api/foods-region.test.ts`**
```ts
describe("GET /api/foods?q=arepa", () => {
  it("returns CO foods first when user.countryCode = CO", async () => {
    // setup: usuario CO + alimento CO "Arepa" + alimento global "Arepa generica"
    const res = await GET(mockRequest({ q: "arepa" }, { countryCode: "CO" }));
    const json = await res.json();
    expect(json.foods[0].regionCode).toBe("CO");
  });

  it("returns global foods first when user has no countryCode", async () => {
    const res = await GET(mockRequest({ q: "arepa" }, { countryCode: null }));
    const json = await res.json();
    expect(json.foods[0].regionCode).toBeNull();
  });
});
```

## Riesgos específicos

| Riesgo | Mitigación |
|---|---|
| Calidad del seed CO (valores de TCA pueden variar) | Cross-check con Tabla de Composición de Alimentos Colombianos del ICBF |
| Alimentos OFF que ya existen pueden duplicarse con regionales | Lógica de dedup por nombre normalizado en seed |
| Usuarios sin `countryCode` (legacy) ven peor búsqueda | El `orderBy` con null es safe; fallback a global |
| Expansión a LAC requiere 40+ alimentos por país | Iteración progresiva; CO es MVP |
